## 二、项目概述

本团队本阶段围绕 **SignLab 实验教学管理系统** 展开设计工作，系统面向高校实验课程教学场景，服务对象主要包括教师、学生和管理员。项目的目标是解决实验课程中课前组织、课堂签到、实验步骤执行、课堂小测、成绩记录、资源上传、数据导入与过程留痕等问题，构建一个覆盖“课程组织—实验执行—过程采集—成绩评价”的教学平台。

结合当前实现情况，系统已经形成较为明确的前后端协同结构：

- 前端采用 `Vue 3 + TypeScript + Vite` 构建，承载登录、学生端、教师端和原型交互展示。
- 后端采用 `Spring Boot 3 + MyBatis Plus + MySQL` 构建，负责认证授权、课程管理、实验流程、课堂小测、成绩管理、微信集成等业务能力。
- 数据库以教学过程数据为核心，围绕用户、课程、班级、实验、步骤、小测、成绩、附件等实体展开建模。

## 三、原型设计

### 3.1 原型设计工具与来源

本项目原型与前端展示主要基于现有前端工程进行整理与复用，前端仓库为：

- 原型/前端来源仓库：`https://gitee.com/zphhpz/newLab`
- 在线原型预览地址：[https://gdutsyjx.gdut.edu.cn/newlab/login](https://gdutsyjx.gdut.edu.cn/newlab/login)

当前前端采用自动路由与模块化页面组织方式，能够直接反映系统的页面原型结构、页面跳转关系与交互流程，因此可作为本次原型设计展示的重要依据。

### 3.2 原型总体结构

从页面层级来看，系统原型主要分为以下三个部分：

1. **登录与身份认证模块**
   - 登录页
   - 微信授权辅助登录
   - 首次登录密码设置
   - 身份校验与登录状态守卫

2. **学生端模块**
   - 课程主页
   - 课程详情页
   - 实验详情页
   - 实验步骤页
   - 课堂小测页
   - 签到页
   - 个人中心
   - 成绩与考勤统计页

3. **教师端模块**
   - 教师总览页
   - 课程管理页
   - 班级管理页
   - 学生管理页
   - 实验管理页
   - 题库与标签管理页
   - 视频管理页
   - 批量导入页

### 3.3 原型页面说明

#### 1. 登录页

登录页作为全系统统一入口，支持用户名密码登录，并为微信授权登录预留入口。该页面结构简洁，重点突出账号输入、密码输入、登录按钮与授权信息反馈，适合作为系统统一认证入口。

#### 2. 学生端原型

学生端以“我的课程”为首页，围绕课程选择、实验执行和学习过程记录展开：

- 学生可在课程列表中查看当前参与课程；
- 进入课程后可查看实验安排、实验步骤与学习任务；
- 实验步骤页支持视频观看、数据收集、题库答题等不同类型的步骤任务；
- 课堂小测模块支持题目作答、历史记录查看与结果反馈；
- 个人中心可展示考勤、成绩、密码设置、系统信息等内容。

#### 3. 教师端原型

教师端采用后台管理风格，总览页集中呈现课程、实验、班级数量与快捷操作入口，适合教师对实验教学整体情况进行统筹管理。教师可进一步进入：

- 课程管理：创建课程、查看课程详情；
- 班级管理：创建班级、绑定班级、导入班级；
- 实验管理：创建实验、编辑实验步骤、查看班级实验详情；
- 用户管理：导入学生或教师；
- 题库管理：维护题目、标签、题目分类；
- 视频管理：上传和查看实验视频资源。

### 3.4 原型交互流程设计

#### 学生端核心流程

1. 学生进入登录页完成身份认证；
2. 登录成功后进入学生首页查看课程列表；
3. 学生选择课程进入课程详情页；
4. 根据实验安排进入实验详情页与步骤页；
5. 完成视频学习、数据填写、附件上传或课堂小测；
6. 系统记录过程数据并在个人中心中展示成绩与考勤。

#### 教师端核心流程

1. 教师登录系统进入后台总览页；
2. 教师可创建课程、配置班级、发布实验任务；
3. 根据实验内容配置步骤、视频、题库、标签与课堂小测；
4. 教师通过导入功能批量录入用户、班级、课程数据；
5. 教师查看学生完成情况、课堂小测成绩与整体统计信息。

### 3.5 原型设计特点

- **角色清晰**：学生端与教师端职责明确，页面组织符合不同角色的使用习惯。
- **流程完整**：覆盖登录、课程管理、实验执行、签到、小测、数据提交等完整业务链路。
- **交互直观**：学生端偏移动式轻交互，教师端偏信息管理式后台布局，符合实际使用场景。
- **便于落地**：前端原型与后端接口结构已经具备较强对应关系，可直接支撑后续实现。

## 四、概要设计

### 4.1 系统总体架构

系统采用典型前后端分离架构，整体分为以下四层：

1. **表示层**
   - 学生端前台页面
   - 教师端后台页面
   - 登录与身份认证页面

2. **业务层**
   - 用户认证与授权
   - 班级与课程管理
   - 实验与步骤管理
   - 课堂小测与题库管理
   - 数据提交与成绩统计
   - 微信集成与资源管理

3. **数据访问层**
   - MyBatis Plus Mapper
   - 实体映射与查询封装
   - SQL 脚本与自动建表机制

4. **数据存储层**
   - MySQL 数据库
   - 文件上传目录
   - 文档与附件资源目录

### 4.2 功能模块划分

#### 1. 认证与权限模块

负责用户登录、密码设置、密码重置、微信绑定、角色鉴权与会话管理。该模块是系统访问控制的基础，决定不同角色能否访问不同业务功能。

#### 2. 教学组织模块

负责班级、课程、学生班级关系的维护，并支持批量导入，解决教师前期建班、排课与数据初始化问题。

#### 3. 实验管理模块

负责实验创建、实验步骤配置、班级实验绑定、实验执行时间控制等，是系统的核心教学业务模块。

#### 4. 实验过程执行模块

面向学生端，负责步骤查看、视频观看、数据收集、附件提交、题库答题、限时小测等具体执行流程。

#### 5. 课堂小测与题库模块

围绕题目、标签、步骤题库映射与课堂小测展开，用于支撑过程性评价和课堂互动。

#### 6. 成绩与统计模块

负责实验得分、课堂小测结果、课程成绩、考勤统计等信息汇总，为教师评价和学生查询提供支持。

#### 7. 资源与扩展模块

包括视频资源、文件下载、二维码签到、微信通知、数据导出等辅助功能，用于提升系统完整性与可用性。

### 4.3 运行逻辑概述

系统运行逻辑总体可概括为：

1. 用户登录后由后端生成身份令牌；
2. 前端基于角色进入对应的学生端或教师端页面；
3. 教师端完成课程、班级、实验与步骤配置；
4. 学生端根据课程与实验安排完成签到、学习、提交与作答；
5. 后端记录过程数据，计算结果，并通过查询接口向前端返回展示内容。

### 5.2 活动图说明

#### 学生完成实验步骤活动图

1. 学生登录系统；
2. 进入课程页；
3. 选择实验；
4. 查看步骤详情；
5. 根据步骤类型执行相应任务；
6. 提交答案、数据或附件；
7. 系统校验并记录结果；
8. 返回步骤完成状态。

#### 教师发布实验活动图

1. 教师登录后台；
2. 创建课程与班级关联；
3. 创建实验；
4. 配置实验步骤；
5. 设置视频、数据收集项、题库或限时小测；
6. 发布班级实验；
7. 学生进入实验执行。

### 5.3 类图说明

从实体结构看，系统主要类之间的关系如下：

- `User` 与 `StudentClassRelation`、`Course` 存在关联；
- `Course` 与 `ClassExperiment`、`CourseGrade` 存在关联；
- `Experiment` 与 `ExperimentalProcedure` 为一对多关系；
- `ExperimentalProcedure` 与 `DataCollection`、`ProcedureTopic`、`VideoFile`、`TimedQuizProcedure` 存在按步骤类型分支关联；
- `ClassroomQuiz` 与 `ClassroomQuizAnswer` 为一对多关系；
- `Topic` 与 `Tag` 通过 `TopicTagMap` 建立多对多关系。

### 5.4 时序图说明

#### 登录时序

1. 用户在前端输入账号密码；
2. 前端向认证控制器发送登录请求；
3. 认证服务验证账号、密码与用户状态；
4. 认证成功后生成 JWT；
5. 后端返回用户信息与令牌；
6. 前端根据角色跳转到学生端或教师端首页。

#### 实验步骤提交时序

1. 学生打开某个实验步骤；
2. 前端请求步骤详情接口；
3. 后端根据当前用户、课程、实验、步骤信息返回对应内容；
4. 学生提交答案或附件；
5. 后端调用步骤提交服务处理数据、保存附件、更新完成状态；
6. 系统返回提交结果并刷新页面状态。

### 5.5 协作图说明

对象协作关系主要包括：

- 前端页面组件与认证接口协作完成登录；
- 教师管理页面与课程、班级、实验、题库相关控制器协作完成教学配置；
- 学生实验页面与步骤查询、步骤提交、成绩统计等服务协作完成实验流程；
- 微信服务与用户、课程提醒、绑定信息等对象协作完成消息通知和身份绑定。

## 六、数据库设计概述

数据库围绕实验教学业务过程展开，当前主要实体包括：

- 用户实体 `User`
- 班级实体 `Class`
- 课程实体 `Course`
- 学生班级关系实体 `StudentClassRelation`
- 实验实体 `Experiment`
- 实验步骤实体 `ExperimentalProcedure`
- 数据收集实体 `DataCollection`
- 题目实体 `Topic`
- 标签实体 `Tag`
- 课堂小测实体 `ClassroomQuiz`
- 课堂小测答题实体 `ClassroomQuizAnswer`
- 成绩实体 `CourseGrade`
- 资源实体 `VideoFile`

设计上采用“基础教学实体 + 过程性任务实体 + 结果性评价实体”的分层思路，既能支撑日常课程管理，也能支持实验过程评价、课堂互动和资源沉淀。

## 九、后端设计展示

### 9.1 后端模块结构

后端目录按职责拆分较为明确，主要包括：

- `controller`：负责请求入口与接口暴露；
- `service`：负责业务逻辑实现；
- `pojo/entity`：负责数据库实体映射；
- `mapper`：负责数据访问；
- `config`、`filter`、`aspect`：负责系统配置、安全控制与角色校验；
- `resources/sql`：负责数据库脚本与迁移。

### 9.2 后端设计亮点

- 采用 JWT 进行无状态认证，便于前后端分离访问控制；
- 通过注解与 AOP 进行角色权限约束，减少控制器中的重复鉴权逻辑；
- 使用 AutoTable 与实体注解配合，提升表结构维护效率；
- 将实验步骤细分为视频、数据收集、题库答题等多种类型，使实验流程可配置、可扩展；
- 课堂小测表与答题表独立设计，便于后续统计、判题和成绩分析。
